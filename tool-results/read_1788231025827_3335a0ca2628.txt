    35→0.1 The Code-Based Authentication System
    36→
    37→The application uses a unified code-based authentication system where different code types grant access to different personas:
    38→
    39→Guest Access Code
    40→
    41→· Generated at Check-In by Reception.
    42→· Time-limited (active until guest checkout).
    43→· Tied to specific Stay, Guest, and Room.
    44→· Grants guest-level access only.
    45→· Automatically expires at checkout.
    46→
    47→Reception Access Code
    48→
    49→· Generated by Admin.
    50→· Time-limited (configurable, e.g., 8-hour shifts).
    51→· Tied to specific Reception staff identity.
    52→· Grants reception-level access.
    53→· Can be revoked at any time.
    54→
    55→Admin Access Code
    56→
    57→· Generated by Master Admin.
    58→· Time-limited (configurable, e.g., 24 hours).
    59→· Tied to specific Admin identity.
    60→· Grants full administrative access.
    61→· Can be revoked at any time.
    62→
    63→Website Booking Code (Tracking Code)
    64→
    65→· Generated at Booking Creation on the website.
    66→· NOT valid for app login.
    67→· Used only for website reservation lookup.
    68→· Expires after Check-In or after a defined period.

   155→2. CORE PRODUCT PRINCIPLES
   156→
   157→2.1 Unified Codebase, Multiple Personas
   158→
   159→The same application binary serves all personas. Authentication via dynamic codes determines what the user sees.
   160→
   161→```text
   162→User Opens App
   163→        ↓
   164→Enter Access Code
   165→        ↓
   166→System Validates Code Type
   167→        ↓
   168→┌───────┴───────┐
   169→│               │
   170→▼               ▼
   171→Guest Mode   Staff/Admin Mode
   172→```
   173→
   174→2.2 Code Lifecycle
   175→
   176→Every access code has a lifecycle:
   177→
   178→```text
   179→┌─────────────────────────────────────────────────────────┐
   180→│                    ACCESS CODE LIFECYCLE                │
   181→│                                                         │
   182→│  GENERATED → ACTIVE → USED → EXPIRED/REVOKED           │
   183→│                                                         │
   184→│  - Guest Code: Generated at Check-In, Expires at Checkout│
   185→│  - Staff Code: Generated by Admin, Time-limited         │
   186→│  - Admin Code: Generated by Master Admin, Time-limited  │
   187→└─────────────────────────────────────────────────────────┘
   188→```
   189→
   190→2.3 Single Source of Truth
   191→
   192→The mobile app is a client that consumes the central hotel platform API.
   193→
   194→· All business logic resides in the backend/API.
   195→· The app displays data, collects input, and shows results.
   196→· No critical business rules are implemented in the app alone.
   197→· The app never modifies data without server-side validation.

   431→5. AUTHENTICATION — THE CODE SYSTEM
   432→
   433→5.1 Code Generation
   434→
   435→Guest Code
   436→
   437→· Generated by Reception during Check-In.
   438→· Format: H{6-digit-numeric}{2-char-checksum} (e.g., H834729X7)
   439→· Tied to: stay_id, guest_id, room_id, hotel_id
   440→· Validity: From generation until checkout or explicit revocation.
   441→· Automatically expires at checkout.
   442→
   443→Reception Code
   444→
   445→· Generated by Admin.
   446→· Format: R{6-digit-numeric}{2-char-checksum} (e.g., R492671M3)
   447→· Tied to: user_id, role_id
   448→· Validity: Configurable (default: 8-hour shift).
   449→· Can be revoked at any time.
   450→
   451→Admin Code
   452→
   453→· Generated by Master Admin.
   454→· Format: A{6-digit-numeric}{2-char-checksum} (e.g., A371849L9)
   455→· Tied to: user_id, role_id
   456→· Validity: Configurable (default: 24 hours).
   457→· Can be revoked at any time.
   458→
   459→Website Tracking Code (NOT for App)
   460→
   461→· Generated by website booking.
   462→· Format: HTL-2026-000421 (human-readable)
   463→· Used only for website reservation lookup.
   464→· Not valid for app login.
   465→
   466→---
   467→
   468→5.2 Code Validation Flow
   469→
   470→```text
   471→User Enters Code
   472→        ↓
   473→System Validates Format
   474→        ↓
   475→System Checks Code Against Database
   476→        ↓
   477→┌───────┴───────┐
   478→│               │
   479→Invalid         Valid
   480→│               │
   481→▼               ▼
   482→Error         Check Expiry & Revocation
   483→Message          │
   484→        ┌───────┴───────┐
   485→        │               │
   486→      Valid           Expired/Revoked
   487→        │               │
   488→        ▼               ▼
   489→    Determine      Show Error
   490→    Code Type        Message
   491→        │
   492→┌───────┼───────┐
   493→│       │       │
   494→▼       ▼       ▼
   495→Guest   Reception  Admin
   496→Mode    Mode      Mode
   497→```
   498→
   499→---
   500→
   501→5.3 Security Requirements
   502→
   503→MUST
   504→
   505→· Codes must be cryptographically secure (not sequential).
   506→· Codes must have checksums to prevent typo-based collisions.
   507→· Codes must be time-limited.
   508→· Codes must be revocable.
   509→· Multiple failed attempts must trigger rate limiting.
   510→· Failed attempts must be logged.
   511→· Code validation must happen server-side.
   512→· Guest codes must be invalidated immediately at checkout.
   513→
   514→MUST NOT
   515→
   516→· Use predictable codes (e.g., incremental numbers).
   517→· Allow brute-force guessing (rate limit).
   518→· Expose code generation algorithm.
   519→· Store codes in plaintext client-side.
   520→· Allow code reuse after expiry.
   521→· Allow admin/reception code to access guest data incorrectly.
