# فندق قلب القاهرة — عدن | تطبيق الفندق (Flutter)

> تطبيق Android لضيوف الفندق وأجهزة الاستقبال اللوحية — **المرحلة F** (نقل تصميم مُجرَّب من تطبيق الويب).
> المرجع السلوكي الوحيد: الواجهة الويب المناظرة + عقد API في `docs/CONTRACTS.md`.

## البنية

```
mobile/
├── lib/
│   ├── main.dart            # الإطلاق
│   ├── app.dart             # MaterialApp + RTL + الثيم + دورة الجلسة (ضيف/استقبال/إدارة)
│   ├── config.dart          # عنوان الخادم (--dart-define أو إدخال المستخدم)
│   ├── core/                # ApiClient (401→renew) + تنسيق عربي
│   ├── models/              # نماذج guest (G-01..G-16) + reception (R-01..R-23)
│   ├── state/               # SessionController + GuestStore + ReceptionStore
│   ├── services/            # RealtimeService (غرف stay:{id} / reception)
│   ├── ui/                  # الثيم (كحلي/ذهبي + Cairo) + مكونات مشتركة
│   └── screens/             # الشاشات (ضيف + استقبال: لوحة/وصولون/مغادرون + المعالجات)
├── android/                 # منصة Android (flavors: dev/prod)
├── test/                    # اختبارات (bun تعادلها: flutter test)
└── assets/                  # خط Cairo + الشعار
```

## التشغيل محليًا

يتطلب Flutter SDK (اختُبر مع 3.29.x):

```bash
cd mobile
flutter pub get
flutter analyze
flutter test

# تشغيل على محاكي/جهاز (نسخة التطوير):
flutter run --flavor dev --dart-define=APP_ENV=dev

# بناء إصدار:
flutter build apk --release --flavor prod --dart-define=APP_ENV=prod --dart-define=API_BASE_URL=https://YOUR-HOTEL-DOMAIN --dart-define=APP_VERSION=1.0.0
```

## عنوان الخادم

- عند البناء بـ `--dart-define=API_BASE_URL=https://…` يصبح العنوان ثابتًا ولا يظهر للمستخدم.
- بدونه: تظهر «إعدادات الخادم» في شاشة الدخول ويُخزَّن العنوان محليًا (لكل بناء dev الافتراضي).
- Realtime: socket.io على `/` مع `XTransformPort=3002` (نفس طوبولوجيا الويب).

## إصدار التطبيق وحد التحديث (F6)

- إصدار البناء يُدمج عبر `--dart-define=APP_VERSION=x.y.z` — CI يستخرجه تلقائيًا من `pubspec.yaml` (الافتراضي المحلي `0.0.0`).
- عند الإطلاق يفحص التطبيق `GET /api/public/app-config` (PUB-07، بلا مصادقة): إن كان `minAppVersion` أعلى من إصدار البناء → شاشة حجب «يتوفر تحديث مطلوب» برابط الإصدارات (قابل للنسخ) وزر «إعادة المحاولة».
- الأدمن يضبط الحد من إعدادات الفندق (A-03: حقل «أقل إصدار مسموح للتطبيق») — فارغ = لا فرض. فشل الفحص متسامح (التطبيق يُكمل تشغيله).

## المصادقة (عقد §1.2.1 — STABLE)

- `POST /api/auth/validate` بالكود → `{token, role, name, expiresAt}` (Bearer، عمر ≤ 12 ساعة).
- `renew` عند الإطلاق/العودة للمقدمة — نفس التوكن يُمدَّد.
- أي 401 نهائي → مسح التوكن → شاشة الكود (بلا refresh-token).

## وضع الاستقبال (F4)

- الدخول بكود `R…` يفتح `ReceptionShell` (موجّه للأجهزة اللوحية): **6 تبويبات** — لوحة التحكم + الوصولون + المقيمون + الطلبات + المغادرون + حالة الغرف (NavigationRail للعرض الواسع / تنقل سفلي للضيق) + زر بحث عام في الهيدر + إشعارات الاستقبال.
- **معالج الوصول (4 خطوات):** تحقق الضيف → تعيين غرفة (متاحة من نفس النوع فقط — R-10) → تأكيد → **كود الضيف يُعرض مرة واحدة** (R-06) مع نسخ وإرسال wa.me (رقم الوجهة قابل للتعديل — قرار W0).
- **معالج الخروج (3 خطوات):** مراجعة الإقامة + ملخص الفاتورة (R-05) → تسوية الرصيد بدفعة سريعة (R-12) أو تأكيد مع رصيد (حوار توكيد) → تنفيذ الخروج (R-07: الغرفة تصبح «تحتاج تنظيف» وكود الضيف يُبطل فورًا).
- **المقيمون (F4-b · R-04):** بطاقات الإقامات النشطة (الغرفة/الرصيد/الطلبات النشطة/موعد الخروج بأحمر إذا حلّ) → تفصيل الإقامة.
- **تفصيل الإقامة (F4-b · R-05):** صفحة كاملة بخمسة تبويبات — الضيف (بيانات + لقطة سعر الليالي + طلبات خاصة) · الفاتورة (الأرصدة + البنود + المدفوعات + تسجيل دفعة R-12/إضافة بند R-13 بحواريهما) · الطلبات (→ تفصيل الطلب) · الرسائل (محادثة فورية مع الضيف R-20/R-21) · الإجراءات (قرارات التمديد R-15/R-16 وتغيير الغرفة R-17/R-18 + محادثة + تسجيل خروج).
- **الطلبات (F4-b · R-08/R-09):** فلاتر الحالات الثمانية + العاجل فقط + تفصيل الطلب بخط زمني وإجراءات الحالة (استلام/إسناد بفريق/تنفيذ/انتظار/إكمال/رفض/إلغاء بتأكيد).
- **لوحة الغرف (F4-b · R-10/R-11):** بطاقات ملونة بحسب الحالة بطوابق + انتقالات التنظيف/خارج الخدمة/الإعادة + عرض إقامة المشغولة.
- **البحث العام (F4-b · R-19):** بالمرجع/الاسم/الهاتف/الغرفة (debounce 350ms) → حجز (وصول أو تفصيل) أو إقامة نشطة.
- Realtime: غرفة `reception` بنفس أحداث الويب (طلب جديد/حجز جديد/رسالة/تحديث إقامة/حالة غرفة) → توست + تحديث كل القوائم (بما فيها المقيمون/الطلبات).
- وضع الإدارة: F5.

## التوقيع والإصدار (CI)

- GitHub Actions: `mobile-ci.yml` (analyze + test) و`mobile-release.yml` (APK موقَّع + GitHub Release).
- مفتاح التوقيع **لا يُرفع للمستودع** — يُحقن من Secrets:
  `KEYSTORE_BASE64` · `KEYSTORE_PASSWORD` · `KEY_ALIAS` · `KEY_PASSWORD`.
- وضع ADMIN فقط: شاشة إرشادية (F5).
