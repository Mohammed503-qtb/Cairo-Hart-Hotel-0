## 2. ما نُفِّذ (القائمة المغلقة حرفيًا)

### 2.1 الملف الجديد src/app/api/auth/renew/route.ts (الملكية)
- `export const dynamic = 'force-dynamic'` كبقية المسارات.
- **rate-limit أولًا**: `rateLimit(`renew:${ip}`, 10, 60_000)` بنمط validate — 429 بالرسالة العربية المتسقة «محاولات كثيرة جدًا. أعد المحاولة بعد N ثانية».
- **المصادقة**: `getAuth(req)` — أي فشل (بلا ترويسة/توكن ملفق/جلسة ملغاة أو منتهية/كود غير ACTIVE/إقامة CLOSED) → `401 «جلسة غير صالحة أو منتهية — سجّل الدخول من جديد»` (حرفيًا نفس أسلوب requireRole).
- **النجاح**: جلب الجلسة بالتوكن (getAuth لا يكشف التوكن) → العمر الجديد = `min(الآن + 12 ساعة، accessCode.expiresAt)` → معاملة واحدة `$transaction`: `session.update({ where: { token }, data: { expiresAt, lastSeenAt } })` + `auditLog.create` — **نفس التوكن يُمدَّد، لا توكن جديد يُصدر** (الرد بلا حقل token أصلًا).
- **التدقيق**: `action: 'AUTH_RENEW'`, entityType `Session`, entityId = session.id, actor = guestName/staffName من سياق AuthContext, actorRole = الدور, details = { role, expiresAt }. (نمط معاملة validate الحرفي — inline داخل $transaction لأن التدقيق جزء من نفس الذرة.)
- الاستجابة: `ok({ expiresAt: <ISO الجديد> })` → `{ ok: true, expiresAt }`.

### 2.2 لمسة lastSeenAt في getAuth (src/lib/auth.ts — التعديل الوحيد المسموح)
- قرار: **نُفِّذت**. السبب: المخاطر مُحيَّدة كلها —
  - الكتابة مرة كل 60 ثانية على الأكثر لكل جلسة (شرط: `!lastSeenAt || now - lastSeenAt > 60s`) — لا كتابة مع كل طلب.
  - مغلَّفة بـ `try/catch` فارغ عمدًا: فشلها (قفل SQLite/انقطاع) لا يُفشل الطلب أبدًا.
  - موضوعة **بعد** فحوص الصلاحية (session/expired/revoked + كود ACTIVE) وقبل تفريع الأدوار — لا تلمس أي حقل صلاحية (revoked/expiresAt للكود تبقى كما هي) ولا تغير أي قيمة إرجاع.
  - `lastSeenAt` ليس جزءًا من أي منطق صلاحية في المنصة (رصد فقط).
- سلوك getAuth قبل/بعد: مطابق 100% (أثبتته الاختبارات + النداءات الحية).
