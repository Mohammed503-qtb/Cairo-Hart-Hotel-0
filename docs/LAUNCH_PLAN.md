## 2) خطة التراجع (rollback)

**الويب:**
```bash
# تراجع كودي عبر سجل last-good (بطاقة IC-6):
cd /opt/cairo-hart
sudo -n systemctl stop cairo-hart-web.service cairo-hart-realtime.service
git checkout --force "$(cat rollbacks/last-good)"
bun install --frozen-lockfile
( cd mini-services/realtime && bun install --frozen-lockfile )
bunx prisma generate && bun run build
sudo -n systemctl start cairo-hart-realtime.service
sleep 2 && sudo -n systemctl start cairo-hart-web.service
curl -fsS -o /dev/null -w '%{http_code}\n' https://$DOMAIN/api/public/hotel
```
- تراجع **بيانات**: آخر نسخة احتياطية عبر `scripts/restore.sh` (IC-2) — «البيانات أغلى من الكود».
- كل نشر يمر ببوابة فحص الصحة في `deploy/deploy.sh` — التراجع غالبًا يُعلن نفسه قبل أن يحتاج أحدٌ إليه.

**الجوال (التطبيق):**
- **الحاجب أولًا**: `minAppVersion` من F6 — الإدارة → إعدادات الفندق → «أقل إصدار مسموح للتطبيق»: يرفعه الأدمن فتُحجب النسخة السيئة عند كل تشغيل وتوجَّه لصفحة الإصدارات (PUB-07 fail-open مع النسخ القديمة جدًا التي تسبق الحارس).
- **إصدار GitHub**: سحب/إخفاء الإصدار السيئ من GitHub Releases (unpublish أو تحويله Latest إلى سابقه) — APK يبقى مثبتًا لدى من حمّله، والحاجب هو ما يوقفه فعليًا.
- ملاحظة موثقة (AUDIT_REPORT MOB-01): الإصدار العام الحالي متقادم — **يجب إصدار APK جديد يحمل الحارس قبل الاعتماد على minAppVersion كسلطة تراجع** (قرار مالك ضمن نطاق F8).

**واتساب (المرحلة 3):** قناته wa.me ثابتة لا تحتاج تراجعًا تقنيًا — عكس القرار (إغلاق زر الإرسال/تغيير رقم الوجهة) قرار إداري من الأدمن مباشرة.

## 3) الإطلاق الناعم (Soft Launch) — ثلاث مراحل

| المرحلة | ماذا يفتح | شرط العبور للمرحلة التالية |
|---|---|---|
| **1 — الويب** | الموقع للضيوف والطاقم (الجوال غير معلن) | **أسبوعان كاملة**: صفر SEV-1 مالي/مصادقة (نفس تعريف F7) · أهداف دعم التشغيل اليومي: النسخ نجح 14/14 ليلة، تنبيه واحد كحد أقصى غير SEV-1 ومعالج من RUNBOOK |
| **2 — التطبيق** | إعلان APK للضيوف والطاقم | **بوابة المتجر** (F8: F1–F4 مقفولة + F7 ناجحة + CI الأخضر + APK جديد يحمل الحارس) + أسبوعا الويب السليمان |
| **3 — واتساب** | قناة wa.me كقناة حجز معلنة للضيوف | **قرار W مستقبلي موثق** (W0 الحالي: بلا مزود — مجرد زر wa.me؛ أي تعميق تقني للقناة قرار جديد) |

> الترتيب مقصود: كل مرحلة تضيف متغيرًا واحدًا فقط — عند العطل نعرف الطبقة المذنبة بلا تخمين.

## 4) قائمة تحقق يوم الإطلاق (حرفية — بالترتيب)

```bash
# نفّذها كمستخدم deploy على الخادم صباح يوم الإطلاق:
sudo -iu deploy
export DOMAIN=$(grep -E '^DOMAIN=' /etc/cairo-hart/env | cut -d= -f2-)
```

1. **مسح بيانات العرض (AD-10):** لا كود/ضيف/حجز عرضي باقٍ —
   المسار المعتمد `scripts/purge-demo.ts` (**غير موجود في المستودع عند 24-c** — البديل الموثق: إبطال كل أكواد طاقم العرض من الإدارة → الطاقم والأكواد، ومعالجة الحجوزات التجريبية من الإدارة → الحجوزات، أو `bunx prisma migrate reset --force && bun prisma/seed.ts` ثم إدخال البيانات الحقيقية قبل الفتح):
   ```bash
   sudo -u deploy sqlite3 /opt/cairo-hart/db/custom.db \
     "SELECT type, status, COUNT(*) FROM access_codes GROUP BY type, status;"
   # راجع القائمة يدويًا: صفر أكواد عرض نشطة
   ```
2. **أكواد طاقم حقيقية:** من الإدارة → الطاقم والأكواد: توليد أكواد الاستقبال/الإدارة الفعلية (مدد 1–30 يومًا حسب العقد) + كودا إدارة (الأصلي + الاحتياطي المختوم لدى المالك — بطاقة IC-3).
3. **نسخة يدوية أولى** (نقطة الاستعادة المعلنة ليوم الإطلاق):
   ```bash
   /opt/cairo-hart/scripts/backup.sh
   sqlite3 "$(ls -1t /var/backups/cairo-hart/daily/*.db | head -n 1)" "PRAGMA quick_check;"
   ```
4. **مراقبة مكثفة 48 ساعة:**
   - الفحص الآلي كل 5 دقائق يعمل (`tail -f /opt/cairo-hart/logs/health.log` أول ساعة).
   - جولة بشرية **كل ساعتين** (أول 48 ساعة): `journalctl -u cairo-hart-web.service -p err --since "2 hours ago" --no-pager` + نظرة على لوحة الاستقبال + المساء عن أول Check-In/Check-Out حقيقيين.
   - نهاية اليوم: تأكيد النسخة الليلية (`ls -lt /var/backups/cairo-hart/daily/ | head -n 2`).

## 5) قرار Go / No-Go

| المعيار | المسؤول عن التأكيد | الحد المطلوب |
|---|---|---|
| قائمة الإقلاع §1 (1–6) كلها مقفولة بتواريخ | **المشغل** (جهّز الأدلة) | صفر بنود مفتوحة |
| تدريب الاستعادة منفذ موثق | **المشغل** (سجل RESTORE_DRILL.md §4) | تاريخ + زمن < ساعة |
| P5 (مفتوح بموثق أو مقفول) | **المالك** (PAYMENT_GATEWAY_DECISION §4) | قرار مسجل بأي حال |
| F7 شهادة الأسبوعين | **المالك** (تشغيل Dogfooding) | صفر SEV-1 مال/مصادقة |
| خطة التراجع مجربة لا نظرية | **المطور** (تجربة IC-6 مرة على الأقل في بيئة الإنتاج قبل يوم الإطلاق) | تجربة موثقة |

**القاعدة:** أي «لا» في جدول القلب (تدريب الاستعادة / P6 / F7) = **No-Go** دون نقاش — الأسبوع القادم موجود. «لا» في P5 وحده لا يمنع (بوابة 8.8 صراحةً).
