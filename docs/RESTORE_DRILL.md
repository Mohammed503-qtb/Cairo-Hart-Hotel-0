# تدريب الاستعادة — RESTORE_DRILL (P2 · بوابة الإطلاق 8.8)

> **فندق قلب القاهرة — عدن** · الحزمة: Task 24-c · شقيق `docs/BACKUP_POLICY.md`
> **هذه الوثيقة هي دليل التشغيل الحي لتدريب الاستعادة** — السجل الذي يثبت أن P2 مقفولة فعلًا لا قولًا.
> نص بوابة الإطلاق 8.8 (MASTER_PLAN §8): «تدريب الاستعادة مُجرى فعليًا (P2) — **هذا البند تحديدًا لا يُقبل بالكلام**».

---

## 1) قواعد التدريب

1. **شهريًا إلزاميًا** — يُنفذ في نافذة هادئة (ليس ذروة استقبال، ليس ليلة نسخ).
2. التدريب الشهري **لا يلمس القاعدة الحية**: يستعيد إلى ملف تجريبي فقط.
3. كل **6 أشهر على الأقل**: تدريب كامل على المسار الحقيقي (`restore.sh` مع إيقاف الخدمات) في نافذة صيانة معلنة للمالك — هذا هو معنى «على خادم نظيف» عمليًا.
4. معيار النجاح: **استعادة نسخة أمس وقراءة أعدادها في أقل من ساعة** (العادة المتوقعة: أقل من 5 دقائق للشهري، وأقل من 20 دقيقة للكامل).
5. أي فشل في خطوة = يُوثَّق كما هو في السجل (§4) + بطاقة تصحيح — الفشل الموثق أفضل من نجاح غير مُجرَّب.
6. المنفّذ يُسجَّل **بالدور** (مشغّل/مالك/مطور) لا بالاسم.

## 2) بروتوكول التدريب الشهري (الملف التجريبي)

```bash
# نفّذها على خادم الإنتاج كمستخدم deploy (الخدمات تبقى تعمل)
sudo -iu deploy

# 1. اختر نسخة الليلة الماضية وتحقق من سلامتها
NEWEST=$(ls -1t /var/backups/cairo-hart/daily/*.db | head -n 1)
echo "النسخة: ${NEWEST}"
sqlite3 "${NEWEST}" "PRAGMA quick_check;"          # يجب أن تطبع: ok

# 2. استعدها إلى ملف تجريبي (عبر .backup — لقطة متناسقة)
sqlite3 "${NEWEST}" ".backup '/tmp/drill-restore.db'"

# 3. اقرأ الأعداد (قارنها مع آخر يومية معروفة من MONITORING/الروتين)
sqlite3 /tmp/drill-restore.db "SELECT COUNT(*) FROM reservations;"
sqlite3 /tmp/drill-restore.db "SELECT COUNT(*) FROM stays;"
sqlite3 /tmp/drill-restore.db "SELECT COUNT(*) FROM guests;"
sqlite3 /tmp/drill-restore.db "SELECT COUNT(*) FROM payments;"
sqlite3 /tmp/drill-restore.db "SELECT COUNT(*) FROM access_codes;"

# 4. نظّف أثر التدريب
rm -f /tmp/drill-restore.db
```

سجّل الزمن من الخطوة 1 حتى آخر أمر قراءة + الأعداد في §4.

## 3) بروتوكول التدريب الكامل (كل 6 أشهر — المسار الحقيقي)

> **قبل البدء:** أبلغ المالك بنافذة الصيانة (متوقع < 20 دقيقة توقف) — الخدمتان ستتوقفان فعلًا.

```bash
sudo -iu deploy

# 1. نسخة أمان إضافية قبل أي تدريب كامل (شبكة أمان فوق شبكة الأمان)
/opt/cairo-hart/scripts/backup.sh

# 2. الاستعادة الفعلية من نسخة أمس (السكربت يفحص سلامتها ويحفظ القاعدة الحالية أولًا)
NEWEST=$(ls -1t /var/backups/cairo-hart/daily/*.db | head -n 1)
sudo -n systemctl stop cairo-hart-web.service cairo-hart-realtime.service
bash /opt/cairo-hart/scripts/restore.sh "${NEWEST}"

# 3. الإقلاع والتحقق الحي
sudo -n systemctl start cairo-hart-realtime.service
sleep 2
sudo -n systemctl start cairo-hart-web.service
export DOMAIN=$(grep -E '^DOMAIN=' /etc/cairo-hart/env | cut -d= -f2-)
curl -fsS -o /dev/null -w 'web: %{http_code}\n' "https://${DOMAIN}/api/public/hotel"
sqlite3 /opt/cairo-hart/db/custom.db "SELECT COUNT(*) FROM reservations; SELECT COUNT(*) FROM stays;"
```

> بعد التدريب الكامل: البيانات الحية = حالة نسخة أمس (ما دخل الليلة التدريبية عاد لحالة الأمس) — **لهذا تُختار نافذة صباحية مبكرة بعد النسخ الليلي مباشرة، وقبل بدء عمل الاستقبال.**

## 5) فشل التدريب — ماذا يعني وماذا يفعل

| العرَض في التدريب | المعنى | الفعل |
|---|---|---|
| `quick_check` ≠ ok على نسخة حديثة | القاعدة الحية أو النسخ تنكسر تدريجيًا | بطاقة RUNBOOK IC-2 فورًا + تصعيد المطور (SEV-1) |
| أعداد غريبة (فجوات كبيرة عن اليومية المعروفة) | النسخة تفقد بيانات بين فترات | راجع `backup.log` لتلك الليالي + تصعيد |
| فشل خطوة استعادة في السكربت | علة في السكربت نفسه | وثّق الخطأ بالنص في §4 + أصلحه قبل نهاية اليوم (سكربت التشغيل عطل = عطل حقيقي) |
| زمن > ساعة | أصول تختنق (قرص/شبكة خارج الموقع) | بطاقة RUNBOOK IC-5 + مراجعة أحجام النسخ |
